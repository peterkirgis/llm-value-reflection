# The Continual Constitutional Convention

What happens when language models are asked to revise the documents that govern
them? Ten models (Claude, GPT, Gemini and Grok, from small to frontier) each
edited a constitution, model spec or system prompt for 20 rounds: one
find-and-replace edit per round, silently applied, with the edited document
handed back as the original. Some chains vary the prompt, and in the
cross-edit condition every model also edits other providers' documents. Each
edit is then coded on two questions: **who judges** (does the edit move
decisions toward the model's own discretion or toward an outside authority?)
and **who benefits** (when an edit puts a cost on one party for another's
benefit, who pays and who gains?). The reported numbers come from three
blinded LLM graders combined by majority vote.

- Website (browse every edit and its coding): https://peterkirgis.github.io/llm-value-reflection/
- Write-up (LessWrong): https://www.lesswrong.com/posts/c9woewdY9ddsPqf3J
- Authors: Peter Kirgis and Tim Hua

## Pipeline

| Stage | Entry point | Reads | Writes | API key / cost | make |
|---|---|---|---|---|---|
| 1. Clean documents | `src/valconv/documents.py` | `constitutions/`, `system_prompts/` | `data/processed/` (gitignored) | no | `make documents` |
| 2. Edit runs | `experiments/iterative_edit/run.py` | `data/processed/`, a config | `run_*.jsonl` | yes, paid | `make api-run` |
| 3. Original coding (coding v1, superseded) | `experiments/iterative_edit/export_changes.py`, then `experiments/iterative_edit/qualitative_code.py` | run files | `results/iterative_edit/judge_beneficiary_coded_gemma.json` | yes, paid | none |
| 4. Canonical edits | `analysis/src/build_phase0.py` | `results/iterative_edit/`, `data/processed/` | `analysis/data/canonical/edits.jsonl` | no | none |
| 5. Blinded grading (coding v2) | `analysis/src/grade.py` | canonical edits, `analysis/prompts/` | `analysis/data/codes/v2_<grader>.jsonl` | yes; free when cached | `make api-grade` |
| 6. Majority vote | `analysis/src/intergrader.py` | the three grader files | `analysis/data/codes/ensemble.jsonl`, agreement report | no | verified by `make check` |
| 7. Statistics and robustness checks (E1-E5) | `analysis/src/headline.py`, `analysis/src/bootstrap.py`, `analysis/src/e_runs.py`, `analysis/src/e_reports.py`, ... | codes files | `analysis/reports/`, `analysis/data/analysis/` | only the E-run grading | none |
| 8. Figures | `analysis/src/report_figures.py` and three more | `analysis/data/codes/ensemble.jsonl` | `analysis/figures/` | no | `make figures` |
| 9. Website | `analysis/src/build_site.py` | `ensemble.jsonl`, `analysis/site_base/`, `reports/final_draft.md` | `docs/` | no | `make site` |

The paid stages (2, 3, 5 and the E-run grading) are done and their outputs are
committed as raw data. [analysis/README.md](analysis/README.md) gives the exact
commands for stages 4 to 9 and explains the coding.

## Quick start

    uv sync          # creates .venv/ with Python 3.12 and every dependency, pytest included
    make test        # the full test suite: offline, about 30 seconds
    make check       # raw-data checksums, majority-vote and website rebuild checks, README paths
    make figures     # redraw analysis/figures/ (reproduces the committed files byte for byte)
    make site        # rebuild docs/ from the consensus codes
    python3 -m http.server 8080 --directory docs     # preview the site at http://localhost:8080

None of these calls an API. `make site` changes only the `generated_at`
timestamps in `docs/data/site.json.gz` and
`analysis/data/analysis/site/selfcheck.json`; discard them with
`git checkout -- docs analysis/data/analysis/site` unless you meant to change
the site. `make documents` is needed only for stages 1, 2 and 4.

To call the APIs, put `OPENROUTER_API_KEY=...` in `.env` (gitignored). Run
`make cache` first: it unpacks the grader cache, and every grading request is
looked up there before the API is called, so repeating a grading run costs
nothing. The API targets refuse to run without `CONFIRM=1`, and `make api-run`
writes new runs to `scratch/runs/`, never into `results/`.

## Raw data

These files cannot be regenerated, or only at real cost, so nothing rewrites
them. `raw_data.sha256` lists all 58 with their checksums; `make check` (or
`shasum -a 256 -c raw_data.sha256`) verifies them.

| What | Where |
|---|---|
| Source documents | `constitutions/`, `system_prompts/` |
| Edit runs: 10 files, 7 of them used (`RELIABLE_RUNS` in `experiments/iterative_edit/viewer/build_static_site.py`) | `results/iterative_edit/run_*.jsonl` |
| Original single-grader codes (coding v1) | `results/iterative_edit/judge_beneficiary_coded_gemma.json`, copied to `analysis/data/codes/v1.jsonl` |
| Canonical edits: 2,740 rounds (2,580 applied edits, 2 abstentions, 158 failed rounds) | `analysis/data/canonical/edits.jsonl` |
| Blinded grader codes, the majority vote, E1-E5 robustness codes | `analysis/data/codes/` |
| Every grader API response (32,293 files) | `analysis/data/raw_api_cache_2026-10-08.tar.gz` |
| Grader prompts, design brief, decisions log, config | `analysis/prompts/`, `analysis/BRIEF.md`, `analysis/DECISIONS.md`, `analysis/config.yaml` |
| Human-coding sample and blind key | `analysis/human/` |
| Hand-made figure-title decisions | `analysis/figures/title_decisions.json` |
| LessWrong draft snapshot | `reports/final_draft.md` |

Already lost: the original `results/` directory went with a local checkout in
July 2026 and was rebuilt from the published site bundle. The rebuild has
everything the analysis uses, but not the full document text after each
round. That text survives in git history for the two earliest runs (see
[archive/README.md](archive/README.md)); for the others it can be replayed
from the source documents (`analysis/src/replay.py`).

The cache archive stores, per request, the model, the parameters, the prompt
hash, a timestamp and the full response text, as
`cache/<first two hex chars>/<cache_key>.json`. The key is the sha256 of the
model, system prompt, user prompt, temperature and extra sampling parameters
(`analysis/src/client.py`); a corrective retry after a schema failure has its
own entry. The archive is deterministic (sorted entries, fixed owner and
mtime, no name or time in the gzip header). `make cache` checks it against
`analysis/data/raw_api_cache_2026-10-08.tar.gz.sha256` and unpacks it into
`analysis/data/cache/`, the gitignored working copy that `client.py` reads.

## Not done yet

- **Human validation and prediction-powered inference (PPI).** A blind sample
  of 180 edits (150 random, 30 picked for adjudication) and a local coding app
  are ready in `analysis/human/`, but no one has coded it yet. The analysis
  scripts (`analysis/src/human_validation.py`, `analysis/src/ppi_analysis.py`)
  are written and tested. Until then the grader codes are not validated
  against human judgment, and `analysis/reports/SUMMARY.md` is preliminary.
- `analysis/` was called `recode/` until 2026-10-08. Frozen inputs inside it
  (`analysis/BRIEF.md`, `analysis/DECISIONS.md`, `analysis/config.yaml`, the
  human-coding files, `analysis/data/derived/` and
  `analysis/figures/title_decisions.json`) are kept byte for byte and still
  say `recode/`; read that as `analysis/`.
